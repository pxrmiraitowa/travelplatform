# 微服务网关联调说明

## 1. 联调目标

本文用于说明旅游平台微服务改造后的本地联调方式。当前联调重点是让前端统一通过 gateway 访问后端，并验证用户、产品、订单、内容行程四类业务服务的主链路可用。

## 2. 服务端口

| 服务 | 端口 | 说明 |
| --- | --- | --- |
| gateway-service | 8000 | 前端统一 API 入口 |
| user-service | 8101 | 登录注册、用户资料、联系人、用户基础信息 |
| product-service | 8102 | 机票、火车票、酒店、旅游产品、价格比对、商品快照 |
| order-service | 8103 | 下单、订单查询、支付模拟、订单状态、评价上下文 |
| content-trip-service | 8104 | 游记、图片上传、行程规划、价格提醒、评价 |
| travel-platform-web | 5173 | Vite 前端开发服务 |

## 3. 启动顺序

建议先初始化本地数据库，再启动四个业务服务和 gateway，最后启动前端。可以手动启动，也可以使用脚本一次启动后查看日志。

数据库初始化：

```powershell
cd C:\Users\han\Desktop\travelplatform\travel-platform-microservices
powershell -ExecutionPolicy Bypass -File .\scripts\init-local-databases.ps1
```

初始化脚本会创建并填充以下本地库：

| 数据库 | 对应服务 |
| --- | --- |
| `travel_user` | user-service |
| `travel_product` | product-service |
| `travel_order` | order-service |
| `travel_content_trip` | content-trip-service |

```powershell
cd C:\Users\han\Desktop\travelplatform\travel-platform-microservices
$env:JAVA_HOME='C:\Program Files\Java\jdk-24'
$env:Path="$env:JAVA_HOME\bin;$env:Path"

& 'C:\Program Files\apache-maven-3.9.11\bin\mvn.cmd' -pl user-service spring-boot:run
& 'C:\Program Files\apache-maven-3.9.11\bin\mvn.cmd' -pl product-service spring-boot:run
& 'C:\Program Files\apache-maven-3.9.11\bin\mvn.cmd' -pl order-service spring-boot:run
& 'C:\Program Files\apache-maven-3.9.11\bin\mvn.cmd' -pl content-trip-service spring-boot:run
& 'C:\Program Files\apache-maven-3.9.11\bin\mvn.cmd' -pl gateway-service spring-boot:run
```

脚本启动：

```powershell
cd C:\Users\han\Desktop\travelplatform\travel-platform-microservices
powershell -ExecutionPolicy Bypass -File .\scripts\start-local-services.ps1
```

脚本会将日志写入 `travel-platform-microservices/logs`，如果服务启动失败，优先查看对应服务的 `.err.log` 和 `.out.log`。如果某个端口已经存在运行中的服务，脚本会跳过该服务，避免重复启动和日志文件占用。

前端启动：

```powershell
cd C:\Users\han\Desktop\travelplatform\travel-platform-web
npm run dev
```

当前前端 Vite 代理已将 `/api` 转发到 `http://localhost:8000`。如果需要绕过代理直连 gateway，可设置 `VITE_API_BASE_URL=http://localhost:8000/api`。

## 5. 最小烟测

可以使用脚本执行 gateway 基础检查：

```powershell
cd C:\Users\han\Desktop\travelplatform\travel-platform-microservices
powershell -ExecutionPolicy Bypass -File .\scripts\smoke-gateway.ps1
```

脚本默认使用 `http://localhost:8000`，也可指定地址：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\smoke-gateway.ps1 -BaseUrl http://localhost:8000
```

烟测覆盖：

| 检查项 | 预期 |
| --- | --- |
| 公开产品接口 | `/api/public/flights` 返回统一响应 |
| 未登录访问保护接口 | `/api/orders` 返回 401 |
| 登录接口 | `/api/auth/login` 返回 token |
| 带 token 查询当前用户 | `/api/users/me` 返回当前用户信息 |
| 普通用户访问后台 | `/api/admin/dashboard` 返回 403 |
| 管理员 dashboard | `/api/admin/dashboard` 返回统计数据 |
| 后台商品路由 | `/api/admin/flights` 返回分页数据 |
| 后台订单路由 | `/api/admin/orders` 返回分页数据 |
| 后台内容路由 | `/api/admin/shares` 返回分页数据 |

默认普通用户测试账号为 `demo_user / 123456`，默认管理员测试账号为 `admin / 123456`。初始化脚本会将这两个演示账号密码校准为 `123456`，确保联调和烟测可复现。如果本地库账号不同，可通过参数覆盖：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\smoke-gateway.ps1 -Username your_user -Password your_password -AdminUsername your_admin -AdminPassword your_admin_password
```

## 6. 业务验收流程

建议按以下顺序完成端到端联调：

1. 访问前端 `http://localhost:5173`，完成登录。
2. 进入机票、火车票、酒店、旅游产品列表和详情页，确认产品查询正常。
3. 选择联系人并提交订单，确认订单进入订单中心。
4. 在订单中心执行支付模拟、完成订单、取消或退款操作。
5. 对已完成订单查询可评价列表并提交评价。
6. 浏览公开游记，登录后发布游记并查看我的游记。
7. 创建、查看、修改、删除行程规划。
8. 在产品详情页查看价格比对，在个人相关入口创建价格提醒。

## 7. 当前注意事项

预订页已经暂时隐藏优惠券选择和优惠后金额，订单金额统一以 order-service 基于 product-service 商品快照计算的金额为准。产品详情页中的价格比对和优惠券展示仍保留，用于说明产品侧价格信息能力。

当前 gateway 负责 JWT 校验和 `X-User-Id` 透传，order-service 与 content-trip-service 通过该请求头识别当前用户。内部服务间调用仍使用固定服务地址配置，后续容器化后需要通过环境变量调整为容器服务名。

后台登录已复用普通登录接口 `/api/auth/login`，后台当前用户信息已复用 `/api/users/me`。目前微服务侧已迁移后台用户、商品、订单、分享和评价管理的第一阶段接口。后台 dashboard 由 user-service 聚合内部统计接口；如果 product-service 或 order-service 未启动，对应统计项会降级为 0，但不影响后台首页打开。商品后台上传图片由 product-service 保存并返回 `/api/public/product-uploads/**`，游记上传图片仍由 content-trip-service 保存并返回 `/api/public/uploads/**`。
