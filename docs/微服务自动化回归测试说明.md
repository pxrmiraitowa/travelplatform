# 微服务自动化回归测试说明

## 1. 测试目标

本说明用于补齐课程要求中的两类自动化证据：

| 要求 | 对应实现 |
| --- | --- |
| 所有后端公开接口都有 API 测试 | `travel-platform-web/regression/public-api.test.js` |
| 清单中的全部业务场景做端到端回归测试 | `travel-platform-web/regression/business-e2e.test.js` |

测试统一通过 gateway `http://localhost:8000/api` 访问业务接口，直接服务端口仅用于健康检查和版本号检查。

## 2. 执行前提

先在项目根目录启动容器化环境：

```powershell
docker compose up --build -d
docker compose ps
```

确认 MySQL、gateway、user-service、product-service、order-service、content-trip-service、frontend 均为 `healthy` 后，在前端目录执行：

```powershell
cd travel-platform-web
npm run test:api
npm run test:e2e
```

也可以一次性执行：

```powershell
npm run test:regression
```

如 gateway 不在默认端口，可通过环境变量指定：

```powershell
$env:API_BASE_URL="http://localhost:8000/api"
npm run test:regression
```

## 3. 公开接口 API 覆盖

| 类别 | 覆盖接口 |
| --- | --- |
| 健康和版本 | gateway `/api/public/health`，user/product/order/content-trip `/api/public/health` 和 `/api/public/version` |
| 认证入口 | `/api/auth/register`、`/api/auth/login` |
| 产品公开接口 | `/api/public/flights`、`/api/public/flights/{id}`、`/api/public/trains`、`/api/public/trains/{id}`、`/api/public/hotels`、`/api/public/hotels/{id}`、`/api/public/tours`、`/api/public/tours/{id}` |
| 价格公开接口 | `/api/public/price-compare/flights/{id}`、`/api/public/price-compare/hotels/{id}`、`/api/public/price-compare/tours/{id}` |
| 内容公开接口 | `/api/public/shares`、`/api/public/shares/{id}` |

| UC09 手动行程规划管理 | 创建行程、查询列表、更新行程、新增/更新/删除每日安排、删除行程 |

## 5. 现场说明建议

展示时建议先运行 `docker compose ps` 证明服务处于 healthy，再运行 `npm run test:api` 和 `npm run test:e2e`。测试通过后，终端会显示每个接口和每个业务用例的通过结果，可作为“所有公开接口 API 测试”和“全部业务场景端到端回归”的直接证据。
