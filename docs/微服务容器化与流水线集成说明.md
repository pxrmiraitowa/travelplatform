# 微服务容器化与流水线集成说明

## 1. 集成来源

本次集成参考新远程仓库 `https://github.com/pxrmiraitowa/travelplatform.git` 的 `dev` 分支，该分支已包含单体后端版本的 Docker Compose、Dockerfile、Nginx 配置和 GitHub Actions 流水线。

由于当前项目已经拆分为 `user-service`、`product-service`、`order-service`、`content-trip-service` 和 `gateway-service`，不能直接合并单体 `dev` 分支，否则会删除当前微服务目录并回退到单体后端。实际采用的策略是在当前微服务稳定分支上新建 `codex/microservices-ci-integration`，选择性迁移容器化和流水线设计。

## 2. 当前集成内容

| 内容 | 说明 |
| --- | --- |
| `.env.example` | 提供本地 Compose 端口、镜像标签、MySQL 密码和 JWT 密钥示例 |
| `docker-compose.yml` | 编排 MySQL、数据库初始化、五个微服务和前端 Nginx |
| `travel-platform-microservices/Dockerfile` | 通过 `SERVICE_NAME` 构建指定 Spring Boot 微服务镜像 |
| `travel-platform-microservices/.dockerignore` | 排除 `target`、日志、上传目录等无关构建上下文 |
| `travel-platform-microservices/scripts/init-local-databases.sh` | Linux/容器环境下初始化 `travel_user`、`travel_product`、`travel_order`、`travel_content_trip` |
| `travel-platform-web/Dockerfile` | 构建 Vue 前端并交给 Nginx 托管 |
| `travel-platform-web/nginx.conf` | 将 `/api/**` 代理到 `gateway-service:8000` |
| `.github/workflows/ci-cd.yml` | 执行微服务 Maven 测试、前端测试/构建和 Docker 镜像构建 |

## 3. 本地容器启动方式

在项目根目录执行：

```powershell
docker compose up --build
```

默认前端入口为：

```text
http://localhost:8088
```

gateway 入口为：

```text
http://localhost:8000
```

如果本机已有 MySQL 占用 `3306`，Compose 默认将容器 MySQL 映射到宿主机 `3307`，不影响容器内部服务访问。

## 4. 验收重点

容器化集成通过后，应重复执行以下验收：

| 验收项 | 预期 |
| --- | --- |
| gateway 健康检查 | `http://localhost:8000/api/public/health` 返回成功 |
| 前端健康检查 | `http://localhost:8088/healthz` 返回 `ok` |
| 登录 | `demo_user / 123456` 可登录 |
| 产品查询 | 机票、酒店、旅游产品接口可通过 gateway 访问 |
| 优惠券下单 | 不选券、选适用券、选不适用券三类结果符合人工验收记录 |
| 订单中心 | 下单后订单可查询、取消 |
| 后台管理 | `admin / 123456` 可登录后台并访问核心管理页面 |

## 5. 后续计划

本阶段先完成本地 Compose 和 CI 基线。下一阶段再将原 `dev` 分支中的 Kubernetes 文件改造成多微服务部署版本，至少需要拆分五个后端 Deployment/Service、补 MySQL 初始化 Job、调整 frontend Nginx 对 gateway 的访问地址，并在 Kind 环境中完成健康检查。

## 6. 当前验证记录

| 检查项 | 命令 | 结果 |
| --- | --- | --- |
| Compose 配置解析 | `docker compose config` | 通过；本机 Docker 配置文件读取有权限警告，但 Compose 文件可正常解析 |
| 微服务后端测试 | `mvn -pl user-service,product-service,order-service,content-trip-service,gateway-service -am test` | 通过 |
| 前端单元测试 | `npm run test:unit` | 通过 |
| 前端生产构建 | `npm run build` | 通过 |
| Docker 镜像构建 | `docker build ...` | 未执行成功；本机 Docker Desktop Linux daemon 未启动，报错为找不到 `dockerDesktopLinuxEngine` |

Docker 镜像构建需要在 Docker Desktop 启动后复验，建议优先构建 `gateway-service` 和 `frontend` 两个代表镜像，再执行完整 `docker compose up --build`。
